Linux NFS 共享存储部署指南：服务端配置、客户端挂载与故障排查

发表于2023-02-14|运维
|总字数:2.8k|阅读时长:10分钟|浏览量:

NFS（Network File System）是 Linux 之间共享目录最常见的方式之一，适合把文件服务器上的目录挂载到多台机器上，例如共享上传目录、日志归档、备份盘或容器持久化目录。

这篇是我对早期 CSDN 笔记的重写版。原笔记把安装、配置、启动、防火墙命令放在同一个代码块里，照着做容易漏步骤；这次按「服务端 → 客户端 → 验证 → 排障」的顺序拆开，每条命令都可以单独复制执行，并补充了生产环境需要注意的权限与安全配置。

生产环境建议

  • 限制访问范围：使用具体客户端 IP 或网段，不要写 *。
  • 避免 777：使用属主、属组和 2770，需要共享给多个用户时通过用户组管理。
  • 默认开启 root_squash：只有明确需要客户端 root 权限时才使用 no_root_squash。
  • 优先 sync：异步写入性能更好，但异常断电时可能丢数据。
  • 最小化防火墙端口：NFSv4 只需要 2049；NFSv3 还需要 rpcbind 和 mountd。
  • 不要长期关闭 SELinux：使用 nfs_export_all_rw 等布尔值和正确的目录标签。
  • 注意 NFS 不提供传输加密：跨不可信网络时，配合 VPN、IPsec 或 Kerberos（sec=krb5）使用。
  • 监控与备份：关注磁盘空间、nfsstat、客户端挂载状态，并备份 /etc/exports 和 /etc/fstab。

目的 命令

查看服务端共享 showmount -e 192.168.1.10

按上面的顺序执行，通常十几分钟就能完成一套可用的 NFS 共享目录。遇到问题时，优先查看 exportfs -v、showmount -e、firewall-cmd --list-services 和 getenforce 这四个输出，大部分原因都能快速定位。
